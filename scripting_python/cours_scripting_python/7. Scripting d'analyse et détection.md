# 1. Analyser des logs, pourquoi ?

Un SOC (Security Operations Center) traite des journaux : firewall, proxy DNS,
flux réseau… Le but : repérer les hôtes compromis. Une fois qu'un poste est
infecté, il doit bien « parler » à son attaquant — c'est le **C2**
(*Command & Control*). Ce trafic est *dans* les logs : encore faut-il le trouver.

`pandas` est l'outil standard pour ce genre d'analyse : charger un CSV, trier,
grouper, agréger, filtrer. Ce module montre comment **trois signaux** différents
révèlent trois façons de se cacher.

# 2. Signal 1 — Le beaconing : détecter le rythme

Un implant « beacon » contacte son serveur C2 à intervalle régulier (ex. toutes
les 60 s), souvent avec un léger **jitter** aléatoire pour ne pas être *trop*
mécanique. Ce rythme laisse une trace statistique : les **temps inter-arrivées**
sont concentrés autour d'une valeur.

On mesure la régularité avec le **coefficient de variation**
`CV = écart-type / moyenne` :

```python
df = df.sort_values("timestamp")
df["dt"] = df.groupby(["src_ip", "domain"])["timestamp"].diff().dt.total_seconds()

stats = (df.dropna(subset=["dt"])
           .groupby(["src_ip", "domain"])["dt"]
           .agg(n="count", moyenne="mean", ecart_type="std"))
stats["cv"] = stats["ecart_type"] / stats["moyenne"]
```

- `cv ≈ 0` → intervalle quasi constant : beacon… **ou tâche planifiée**.
- `cv` élevé → navigation humaine, irrégulière.

> [!warning] Le piège des mises à jour légitimes
> `windowsupdate.com`, `ntp.org`, les antivirus sont *eux aussi* périodiques.
> On les écarte via une **liste blanche** de domaines connus, et on croise avec
> la **stabilité du payload** : un beacon envoie toujours la même taille.

# 3. Signal 2 — Le fast-flux : compter les destinations

Pour échapper au signal précédent, un C2 peut **changer d'IP et de domaine** à
chaque connexion (fast-flux, DGA). Grouper par domaine ne donne plus rien : chaque
domaine n'apparaît qu'une fois.

On change de point de vue : on regarde l'hôte **source**.

```python
df.groupby("src_ip")["dst_ip"].nunique()
```

Un hôte légitime contacte un petit nombre de destinations **partagées**. Un hôte
en fast-flux contacte un grand nombre d'IP **rares** — contactées par lui seul.

# 4. Signal 3 — La plage d'IP : quand il n'y a plus de rythme

Un implant sophistiqué **randomise totalement** son timing : plus aucun CV
exploitable. Mais il doit toujours joindre son serveur C2, hébergé dans un `/24`
que l'entreprise ne contacte jamais. On réduit chaque IP à son préfixe :

```python
def prefixe(ip: str) -> str:
    return ".".join(ip.split(".")[:3]) + ".0/24"
```

On cherche alors les préfixes **rares** (contactés par une seule source) **et**
massivement contactés. C'est la détection *par la destination*, pas par le rythme.
