## 1.2 Module argparse

`argparse` et un module inclus dans la lib standard de python, qui permet de parser les aguments passés à un programme appellé depuis un terminal.

## [!example] Example d'utilisation du module argparse
  
  On définit un fichier `myscript.py`:
```python
import argparse
import sys

if __name__ == "__main__":
	print(f"argumrents bruts: {sys.argv}")
	
	parser = argparse.ArgumentParser(description='Argparse demo')
	parser.add_argument("--name")
	parser.add_argument("--year", type=int)
	args = parser.parse_args()
	
	print(f"Bonjour {args.name}, bienvenue en {args.year} !")
```  

On peut alors exécuter le script avec la commande suivante:
```shell
$ python myscript.py --name franck --year 2024
```

# 4. Aparté cyber — Les librairies publiques comme vecteur d'attaque

## 4.1 Exemple: event-stream (`npm`), en 2018

https://blog.npmjs.org/post/180565383195/details-about-the-event-stream-incident


> [!info] L'histoire en 4 temps
> 1. [`event-stream`](https://www.npmjs.com/package/event-stream): petit package utilitaire, **~1,5 M téléchargements/semaine**. Plus de développement en cours.
> 2. Un inconnu propose de « reprendre la maintenance » — l'auteur accepte et lui transfère les droits.
> 3. Nouvelle version avec dépendance piégée `flatmap-stream` : code de vol de wallets Bitcoin.
> 4. Détection plusieurs semaines après : des milliers de projets contaminés via dépendances transitives.

## 4.2 Vecteurs d'installation

| Vecteur              | Mécanisme                                                                                                       | Cas réel                                                 | Ce qui trahit                                                            |
| -------------------- | --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------ |
| Typosquatting        | Nom quasi identique au package légitime (`requets` vs `requests`)                                               | Vagues PyPI régulières                                   | Faute de frappe, 0 étoile, auteur inconnu                                |
| Reprise / transfert  | Mainteneur fatigué cède le projet à un inconnu                                                                  | `event-stream` (npm, 2018)                               | Changement d'auteur + version soudaine + nouvelle dépendance             |
| Dependency confusion | Package interne non publié : l'attaquant publie le même nom en public avec version haute, `pip` prend le public | Clipboard researcher, 2021 (Apple, Microsoft concernées) | Nom interne résolu depuis le registre public, version anormalement haute |
| Backdoor mainteneur  | Compromission ou pression sur un mainteneur légitime                                                            | `xz-utils` (2024, backdoor SSH avortée de justesse)      | Commits suspects, binaires opaques, urgence à mettre à jour              |

## 4.3 Méthodes d'exécution

1. Exécution de code malveillant **à l'installation** (`setup.py`). 
2. Exécution de code malveillant dans le programme qui importe la librairie.

## 4.4 Les 4 réflexes défensifs (5 min)

1. **Jamais `sudo pip`.** Un package compromis hérite de vos droits — limitez la casse.
2. **Vérifier avant d'installer.** Nom exact, auteur, page PyPI, page github, date et changelog. En cas de doute : ne pas installer.
3. **Pinner + vérifier l'intégrité.** `pip freeze > requirements.txt`, `--require-hashes` en prod, hash SHA256 du sdist (rappel `hashlib` modules 1-2).
   (les utilitaires modernes comme `uv` ou `pdm` font ça automatiquement).
4. **Auditer l'existant.** `pip show <pkg>`, `pip audit`.
