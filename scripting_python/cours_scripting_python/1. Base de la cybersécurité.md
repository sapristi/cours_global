# 1. La cybersécurité, c'est quoi ?

[!note cours] Commencer par questionner les élèves sur ce qu'ils considèrent être la cybersécurité.


> [!abstract] Définition
> Protéger les systèmes, réseaux et données contre les attaques, les vols et les interruptions.

- La plupart des infrastructures sont connectées : hôpitaux, banques, usines, téléphones
- Une panne = vies, argent, confiance en jeu

Exemples :

- **Ransomware :** hôpital paralysé
- **Fuite :** mots de passe, informations personnelles revendus

## 1.1 Qui attaque, qui défend ?

> [!danger] ⚔️ Les attaquants ( red team )
> - Cybercriminels (ransomware, arnaques)
> - États (espionnage, sabotage)
> - Hacktivistes, insiders
> - pentesters

> [!info] 🛡️ Les défenseurs ( blue team )
> - SOC (security operations center) 
> - CERT (computer emergency response team)
> - RSSI, devs

# 3. Exemples de menaces

[!note cours] Quelles types de menaces / d'attaques connaissez vous ?

1. Brute-force / stuffing — SSH, web
2. Injection — SQL, XSS, Commande
3. Phishing — hash, URL
4. Scan / énumération — `socket`, ports
5. Exfiltration / C2 — DNS tunneling

## 3.1 Menace 1 — Brute-force / credential stuffing

- **Quoi :** deviner un mot de passe en testant systématiquement des milliers de combinaisons.
- **Brute-force :** on génère les essais (wordlist, dictionnaire). **Stuffing :** on rejoue des logins/mdp volés dans des fuites — les gens réutilisent leurs mots de passe !
- Cibles : SSH, RDP, formulaires web, API.
- Pourquoi ça marche encore : mots de passe courts, prévisibles (`Azerty123`), jamais changés.
- **Défenses :** MFA, limiter les tentatives (rate-limit), bannir après N échecs (fail2ban), mots de passe longs.

## 3.2 Menace 2 — Injection

- **Quoi :** une entrée utilisateur est interprétée comme du code → l'attaquant exécute ses propres ordres.
- **SQL :** taper `' OR '1'='1` dans le login contourne l'authentification en truquant la requête SQL.
- **Commande :** un `; id` glissé dans un champ s'exécute sur le serveur si l'entrée est concaténée dans un appel système.
- **XSS :** un script injecté dans une page vole le cookie de session des visiteurs.
- **Défenses :** requêtes paramétrées, validation stricte des entrées, jamais de concaténation, messages d'erreur génériques (le détail aide l'attaquant).

## 3.3 Menace 3 — Phishing

- **Quoi :** le phishing (mail piégé) est le 1er vecteur d'accès initial : un clic suffit.
- **Indices** : expéditeur imité, urgence artificielle (« compte bloqué »), pièce jointe ou lien inattendu, URL qui n'est pas le vrai domaine, impersonation d'une personne importante (CEO).
- **Hash SHA256 = carte d'identité du fichier :** 1 bit change → hash totalement différent ; on compare aux bases d'IOC connus.
- **Défenses :** ne jamais ouvrir dans le doute, vérifier l'URL, l'expéditeur, demander confirmation par un autre canal.

## 3.4 Menace 4 — Scan / énumération

- **Quoi :** cartographier une cible : quels ports sont ouverts, quels services et versions tournent.
- Ports ouverts = portes d'entrée potentielles ; la version du service dit s'il est vulnérable.
- Bannières et réponses verbeuses en révèlent trop : un serveur qui se présente aide l'attaquant.
- Étape **Reconnaissance** de la Kill Chain : tout commence par observer, bien avant d'attaquer.

## 3.5 Menace 5 — Exfiltration / C2

- **Quoi :** une fois dedans, l'attaquant vole des données (exfiltration) et garde le contrôle via un canal de commande (C2).
- **Beaconing :** le poste compromis « appelle » le serveur de l'attaquant à intervalles réguliers — discret car sortant.
- **DNS tunneling :** des données cachées dans des requêtes DNS, un protocole que personne ne bloque.

# 4. Exemples de défense

## 4.1 Principes

- **Défense en profondeur** : Firewall + auth + logs.
- **Principe de moindre privilège** : Faire en sorte de donner à quelqu'un les droits minimum dont il a besoin.
- **Zero Trust** : Chaque requête vérifiée + loggée.
## 4.2 Hygiène

- Mots de passe longs + uniques + gestionnaire
- **MFA**
- Sauvegardes testées
- Logs : qui, quoi, quand — et on les protège
## 4.3 Crypto utile + démo

- **Hash** (intégrité) : `SHA256` = empreinte. Vérifie mdp
- **Symétrique** : 1 clé (AES). Rapide, partage délicat.
- **Asymétrique** : publique/privée (RSA). Échange + signatures.

```python
import hashlib

# Démo 2 min : intégrité
def sha256_texte(t: str) -> str:
    return hashlib.sha256(t.encode()).hexdigest()

print(sha256_texte("motdepasse123"))
# vérif log : recalculer et comparer
```

> [!note] À retenir
> **hash = détecter la modification, chiffrement = empêcher la lecture**.
